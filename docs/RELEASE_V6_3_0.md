# v6.3.0 — Product waves and accountable handoffs

This compatible minor release prepares agents to advance the nearest authorized
product work, release independent accepted units, and preserve unfinished work
with an owner and next action. Publication is established by the exact-tag CI
and downloaded assets, separately from these source notes.

## Changed behavior

- Coordinators select useful work at settlement, wave and material blocker
  boundaries. A waiting build permits independent work with disjoint ownership;
  busy writers and candidates under acceptance remain protected.
- Release boundaries follow actual API, schema, auth and configuration
  dependencies. An isolated failed outcome can carry into the next wave while
  independent accepted value ships. A critical shared dependency still blocks
  its dependent units.
- A bounded task/wave handoff validator checks exact artifact and local evidence
  hashes, declared outcomes, arithmetic, release references, owned carryover
  and next-wave decisions. Accepted and shipped counts stay separate. Without
  a declared denominator, it reports counts and unavailable percentages.
- Stop reports specific handoff errors separately from writing diagnostics.
  Repeated identical failures remain unresolved without an automatic repair
  loop. Mailbox acknowledgements do not require a substantive handoff.
- Planning reuses persona/journey findings and project evidence. AI personas
  remain hypotheses; route existence alone does not establish a useful journey.
- Shared UI recipes preserve source discovery, existing tokens/components/assets,
  finite motion and font/image geometry checks. Optional image exploration does
  not certify interactive, responsive, consumer, device or production behavior.
- Verification follows changed behavior and blast radius, reuses exact-state
  evidence, and reserves broad integration for meaningful boundaries. Mandatory
  security, data, auth, CI and release checks remain required.
- Installed runtime tests no longer impose generator assertions on project-owned
  setup files. Generator assertions retain source-only negative coverage.
- Work observation adds an explicit Windows contained-process worker option,
  keeping free-space probes responsive during scans. Default inline behavior
  remains unchanged. Sampled logical bytes are neither an OS quota nor an
  atomic snapshot; incomplete/unsafe observations still fail closed.
- The optional measured scan-envelope test receives its immutable input through
  `MANAGED_TEMP_SCAN_ENVELOPE_INPUT`, retaining source manifests and the measured
  957-file/40,677,455-byte assertions. No private machine path is shipped.

## Evidence and limits

Focused checks cover partial closure, independent/dependent release decisions,
busy ownership, waiting gates, stale findings, image-proof limits and unchanged
test reuse. Handoff fixtures cover local-reference boundaries, corrupt receipts,
unknown denominators and Stop deduplication. The portable-input selector covers
missing, blank, unresolved, file and valid-directory inputs.

These checks establish their declared source, schema and synthetic-handler
contracts. Local owner-attested release receipts do not independently prove a
deployment. Ordinary host activation, downstream installation, actual product
builds, browser/device acceptance, spending and quota savings are not inferred.
The historical observer workload and its failures remain separate evidence;
this release does not declare that product build accepted.

## Installation and rollback

Node 24+ and existing host trust/library setup requirements remain in force.
No project-wide model, effort, approval or sandbox defaults change. Books,
private evidence, local receipts and caches remain outside the public archive.
Existing projects update only through a separately authorized exact-tag preview
and digest-bound apply. Preserve project overlays and use the updater's rollback
contract. Publication of this release does not update any consumer.

Before claiming publication, verify the immutable source commit, successful
Linux/Windows preflight, exact-tag release jobs, stable non-draft release,
downloaded SHA256SUMS/metadata, and matching canonical Git archive.
