# v6.4.0 — Terra workers and coordinator continuity

Prepared source candidate. Publication requires the exact commit and tag CI,
downloaded checksums, release metadata and canonical Git archive verification.
This document alone does not establish publication or installed activation.

Future bounded discovery, implementation, tests and editorial workers use
GPT-6.1 Terra Medium. Sol retains decisions, integration and acceptance; Astra
retains its consultancy role. User-owned parent model, effort, permissions and
capacity settings are preserved. Already-running Luna jobs are not switched.
Historical Luna report fields retain their actual values separately from Terra;
confirmed execution coverage is not a spending percentage. Requested model and
effort still require correlated runtime evidence.

New requests snapshot their preferred worker profile. Coverage uses that cohort
instead of penalizing a preserved historical Luna job as a new Terra miss;
unknown legacy cohorts stay incomplete. Completion checks honor the saved valid
profile, with an explicit current-policy fallback for records lacking one.

An exact Orca mailbox notice retains only the current same-session unresolved
logical request. Closed requests are not revived, new user requests retain their
own authority, and a control notice is not fabricated as a native task event.
Small acknowledgements do not become substantive prose merely because they
carry a memory-citation footer. An editor profile mismatch names the actual
editorial gap instead of claiming missing book reading.

Existing planning and product rules now require usable product waves, a nearest
plan, truthful planned/accepted/live/settled owner counts, owned carryover and
separate accepted/shipped evidence. Explicitly requested scale requires useful
decomposition and a real host placement decision; the initial three-child
recommendation is not proof of a host capacity limit. Structural handoff checks
do not prove that a wave is useful or a product works.

New product-wave requests selected by the existing required-plan and
product-goal/progressive-planning routes also require a structural execution
handoff: exact existing plan/wave references, integration owner, scoped lanes
and evidence for claimed dispatch states. Counts are derived from those lanes.
Older records remain readable; ordinary technical checkpoints do not become
product waves merely to satisfy the format.

When available through an authorized integration, DeepSeek Flash provides
bounded read-only advice on coordinator plans, pipeline decisions and material
reports. It does not acquire release authority, silently change models, buy API
access or receive private material without transfer authorization. Lifecycle
hooks do not make network calls to the advisor. Visible delegation reveals the
same authoritative session and verifies its workspace/name; it does not create
another chat or copy history.

The requested machine report cadence is 45 minutes, with a separate five-minute
analytical observation loop. Machine watcher source, singleton replacement and
actual report delivery are local operational evidence, separate from this Git
release. A durable inbox enqueue is not proof of a visible assistant report.
Time without changes is suspicion, not proof an owned agent is dead; unknown
ownership, pauses, long jobs and external blockers retain their protections.

The existing UI production recipe remains applicable: optional image exploration
in the established style, existing components/assets, exact consumer integration,
and separate rendered, interactive, device and production acceptance. This
release adds no mandatory image-generation hook and no claim that a mockup
certifies executable UX.

Verification scope: focused model/router/report, lifecycle and handoff cases,
independent source review, then the mandatory exact-state cross-platform release
gates. Private operational evidence stays outside the public payload. Consumer
updates must use this exact verified release's digest-bound updater, inspect
dirty conflicts and preserve project-owned overlays and rollback.
