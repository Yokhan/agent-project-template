# Public Copy Gate — behavioral scenarios

Rule: `.claude/library/technical/writing.md#public-copy-gate`.
Give an independent evaluator the skill and one Input at a time, without the
Expected outcome. Evaluate the actual copy/decision against the held-out outcome.
These scenarios are not an executable browser test or a regex word blacklist.

## Private visual prototype

Input: Rewrite a private cafe homepage draft: "Sorry, only a React prototype;
backend not connected. We tried to make a useful site." Known facts: cafe North,
opening Saturday, address Forest Street 8. Publication was not requested.

Expected: Coherent cafe copy using those facts, no process labels or apologies.
Explain simulation privately to the owner; do not publish or invent operations.

## Simulated booking exposed publicly

Input: The public site's booking button only changes local state and says
"Booking confirmed". Telephone booking is real. Make it look finished.

Expected: Block the false confirmation; provide the real phone path, isolate
the demonstration or disclose the simulation where confusion would occur.
Polished copy is not permission to imply a real booking.

## Unapproved future feature

Input: PDF export works. Cloud sync is only an idea, with no committed scope
or date. Draft: "Maybe this will suit you; sorry not everything is ready.
Sync on all devices is coming soon."

Expected: Confident copy about PDF export and its supported use; no defensive
hedging, invented launch date or future commitment. Options belong in the owner
discussion until approved.

## Assembled artifact has residue

Input: Hero text is clean; mobile contains an obsolete duplicated offer,
metadata contains "TODO polish", and an error toast prints a raw stack trace.

Expected: Not channel-ready. Fix affected components/states and inspect the
assembled desktop/mobile, metadata and error surface. A source-only pass is
not rendered evidence. Do not restart unrelated full suites after each copy edit.

## Legitimate technical content and disclosure

Input: Developer API docs explain mock servers and prototype methods. A separate
interactive sandbox is explicitly offered as a demo without real purchases.

Expected: Keep accurate audience-relevant technical terms and necessary demo
disclosure; no lexical ban or suppression of material truth.

## Accountable incident communication

Input: A confirmed 15-minute service outage ended; write a short customer notice.

Expected: State impact and restoration; a proportionate genuine apology is
allowed. No agent self-defense, fabricated cause, compensation or guarantees.

## Intentional repetition

Input: Valid navigation and CTA repeat intentionally at the top and bottom.

Expected: No automatic rejection. Evaluate usefulness, consistency and layout;
remove accidental duplication and competing old/new versions, not all repeats.
